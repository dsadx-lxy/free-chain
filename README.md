# 高分子链构象计算器

输入链段数 **n**，得到末端距 **h**。

软件默认使用**自由连接链（FJC）**模型，并内置**自由旋转链、受阻旋转链、蠕虫状链**
另外三个模型，可在页面上随时切换对照。下面先讲默认模型，四个模型的完整对照见
「四个链模型」一节。

模型下拉里的第五项是**自回避行走（SAW）**：给链加上「不许重复访问同一个格点」
这条约束之后，⟨R²⟩ **不再** ∝ n，而是 ∝ n^(2ν) —— 见「自回避行走」一节。

它和那四个**不是一类**，这一点写在页面上也写在代码里：那四个模型的 ⟨h²⟩ 都有闭式解，
力–伸长、h→n 反解、模型指纹、数值表这些「按公式算」的功能全都成立；SAW 没有闭式解，
只能实空间采样，上面那些一张都算不了。所以**选中 SAW 时，页面上这些卡片会收起来**
（判据是 `/api/models` 里每项的 `analytic` 位），页面只留它算得出来的东西。

那四个模型里又只有**受阻旋转链**（内旋转势垒）与**蠕虫状链**（弯曲刚度）有真正的
**能量自由度**，所以另有一张按模型显隐的「能量图景」卡 —— 见「能量图景」一节。

自由连接链模型（Freely Jointed Chain）：链由 n 个长度为 l 的链段自由连接，
无键角限制、无位阻，各链段取向互相独立。由此均方末端距

> **⟨h²⟩ = n·l²**，即 **h = l·√n**

`⟨h²⟩ = n·l²` 对 FJC 是**精确解**（不是近似），因为链段方向两两独立，
交叉项 ⟨lᵢ·lⱼ⟩ = 0。末端距的**分布** P(h) 用的是 n 较大时的高斯近似。

### 改 `启动.cmd` 之前先看这条

这个文件有两条硬约束，破坏任意一条都会导致**双击后一闪而过、什么都不发生**：

1. **行尾必须是 CRLF**，不能是 LF。
2. **文件内容必须是纯 ASCII**，不能出现中文（连注释里也不行）。

原因是 `cmd.exe` 按 OEM 代码页（这里是 GBK）逐字节读取 .cmd 文件。UTF-8 的汉字是
3 字节、GBK 是 2 字节，一旦错位就会把相邻的行结构冲垮，解析器开始把 `--open`
当成 `--op` + `ho` 去执行。行尾是 LF 时更容易触发。

中文只应该出现在网页和 `server.py` 里 —— Python 通过 Windows 控制台 API 输出，
不受代码页影响。这条教训 `明账FMS` 的启动器头部也记着。

用 VS Code 之类的编辑器改完这个文件，记得确认它没把行尾改回 LF。

## 页面能算什么

| 量 | 公式 | 说明 |
|---|---|---|
| 均方末端距 ⟨h²⟩ | n·l² | 精确 |
| 根均方末端距 h_rms | l·√n | 主输出，即「输入 n 得到 h」的 h |
| 最可几末端距 h* | l·√(2n/3) | P(h) 的极大值点 |
| 平均末端距 ⟨h⟩ | l·√(8n/(3π)) | ≈ 0.9213·l·√n |
| 分布标准差 σ | l·√(n/3) | 由 ⟨h²⟩ − h*² 推出 |
| 回转半径 Rg | √(n·l²/6) | ⟨Rg²⟩ = ⟨h²⟩/6 |
| 全伸展长度 | n·l | 高斯分布在 h > nl 的尾巴无物理意义 |
| 特征比 Cn | ⟨h²⟩/(n·l²) ≡ 1 | FJC 的定义性特征 |
| 径向分布 P(h) | (β/√π)³·4πh²·e^(−β²h²) | β = √(3/(2nl²))，∫₀^∞ P dh = 1 |

序关系恒为 **h\* < ⟨h⟩ < h_rms < nl**（n=100, l=1 时：8.165 < 9.213 < 10 < 100）。

**多重对比**：n 栏可以填逗号分隔的多个值（最多 5 个），如 `10, 100, 1000`，
曲线会叠加。n 栏下面那排**快捷值**（10 … 10000）点一下即加入、再点移出，
就是用来快速凑一组对比的。

**归一化显示**：勾上后横轴改为 h/h_rms、纵轴改为 P·h_rms，各 n 的曲线会**精确重合**：

> h_rms·P(h_rms·x) = 4·(3/2)^1.5/√π · x²·e^(−1.5x²) ≈ 4.14624 · x²·e^(−1.5x²)

这条式子与 n、l 都无关 —— 说明 √n 标度律在**整个分布**上都成立，
而不只是均方值 ⟨h²⟩ = nl² 成立。（`test_scaling_collapse` 就是验这个的。）

## 页面结构

页面分四节，仍是**一页四节**（没有改成真的翻页）。导航有**两种形态**、同一份标记：

- **宽屏 ≥900px**：四个分区标签排成**左侧竖列**（164px 的 rail），
  点击平滑滚动跳到那一节；正文整体右移，rail 和正文之间一条贯穿全页的竖线分界。
  rail 吸顶（`position: sticky`），滚动时一直跟着。
- **窄屏 <900px**：退回**顶部横条**，吸顶在 App Bar 上面。

两种形态都跑同一套 **scrollspy**：滚到哪节高亮哪个、点击平滑跳转、滚到底钉住最后一个。
栏高量出来写进 `--bar-h` / `--nav-h`，标题和分区导语不会被吸顶栏盖住。
分区是会**整个消失**的（见下面那张表），所以它每次同步都现筛一遍可见分区 ——
`display:none` 的元素 `getBoundingClientRect().top` 恒为 0，不筛的话收起来的数值表
会永远满足「top ≤ 偏移」而霸住高亮，滚到底那条也会把高亮钉在一个看不见的分区上。

四节各自装什么：

| 分区 | 里面有什么 |
|---|---|
| 参数与结果 | n / l / 归一化、**链模型（四个解析模型 + 自回避行走）**、**Kuhn 长度预置**、**h → n 反解**、主结果大字、统计量卡片 |
| 可视化 | P(h) ‖ 3D 单链构象 —— 系综分布和一次随机实现**特意同屏** |
| 标度验证 | **力–伸长曲线（Langevin）**、链长扫描、**自回避行走**、模型指纹、**能量图景**（只有受阻旋转链与蠕虫状链有）—— 都是在验什么，所以放一节 |
| 数值表 | 全部统计量，制表符分隔，一键复制进 Excel |

**选不同模型时，这几节里显示的东西不一样**（选中 SAW 后）：

| 收起 | 留着 | 为什么 |
|---|---|---|
| 主结果大字与七张统计卡、P(h) 分布、h → n 反解、力–伸长、**链长扫描**、模型指纹、整个数值表分区（含导航里那个入口） | Kuhn 长度预置、3D 链构象（改成并排两团格点链）、自回避行走卡 | 收起来的那些全部出自 `/api/compute`、`/api/force`、`/api/model-curves`、`/api/sweep`，都要求闭式 ⟨h²⟩；Kuhn 预置只是把 `l` 填成某个 `b`，SAW 也吃 `l`。链长扫描收起不是因为它算不了 n 的幂律，而是那条斜率 1 的**参考线**与 ⟨R²⟩=n·l² 的理想链理论出自同一个闭式解 —— 自回避的对应物是它自己那张卡（参考线换成 2ν、各点误差棒换成实测值） |

收起是**不取数**，不是取回来再藏起来：`refresh()` / `refreshForce()` / 指纹卡各自提前
返回，所以切到 SAW 时不会打那三个接口、也不会在告警条上挂一条 400。扫描卡本来就要点
「运行模拟」才取数，`sweep.js` 的 `run()` 里另有一条守卫，防的是将来别处去调它。

显隐机制写在样式里、不写在脚本里：要收起的元素在 HTML 上标 `data-only="analytic"`
或 `data-only="simulated"`，`syncModelFields()` 把当前模型那一类写进
`<body data-model-kind>`，其余交给几条属性选择器。**没走 `[hidden]`** ——
`.card, .hero` 是 `display:flex`，它会盖掉 `[hidden]` 的 `display:none`，
这个坑仓库里踩过一次（`.ai-drawer[hidden]` 那两条就是补它的）。属性选择器还顺带
解决了首帧：脚本还没跑、目录还没拉回来时，`[data-only="simulated"]` 就已经是隐藏的，
不会先闪一下 SAW 的卡片再收回去。

同一个漏斗还写第二个属性 `<body data-model>`（具体是哪个模型），给**能量图景**那张卡用。
它不能只靠上面那个二分类：这张卡会在类别**不变**的时候出现或消失（fjc → wlc 两边
都是 analytic），所以它按模型而不是按类别显隐。两个属性任一变了都要重挑当前分区、
重摆占位虚框，`syncModelFields()` 里就是这么判的。

**几何计算**分了两条路：**重新夹边界**只遍历**可见**卡片（`visibleCards()`）。它用
`getBoundingClientRect()` 量尺寸，而 `display:none` 的元素量出来全是 0 —— 不筛的话，
一次窗口 resize 就会把一个**错位**的偏移写回隐藏卡片（再显示出来时跑到别处去）。
**虚线占位框**正相反，走的是全量 `cardEls()`：收起的卡片得把它的框**去掉**，只遍历
可见的话那个框会一直挂在分区里（`syncGhosts()` 里那句「收起了：不留框」就是干这个的）。
**存取偏移本身也走全量**（`saveCardPos()` 是从零重建整份记录，按可见性过滤会把
隐藏卡片已存的偏移悄悄删掉）。

顺带补上的三件交互：

- **URL 状态**：`?n=…&l=…&norm=1` 会写进地址栏，刷新或分享链接都以 URL 为准，
  其次才是 localStorage，最后才是默认值。
- **记住上次参数 + 一键重置**：「恢复默认」把 n / l / 归一化连同 Kuhn 与反解的读数一起清掉。
  只有**计算成功**才写状态，打错字的中间值不会覆盖好状态。
- **四张 SVG 图都能导出 PNG**（P(h)、力–伸长、链长扫描、自回避行走）。导出走 `app.js` 里共用的
  `svgToPng`：把每个元素的计算样式内联进克隆树、垫底色、再按 2× 光栅化 ——
  序列化的 SVG 是独立文件，看不见 `style.css` 也读不到 `var(--series-*)`，不内联一定丢颜色。
  垫的那层底色读每个主题下的 `--png-bg`（面板本身是半透明的，照它垫底会导出
  一张半透明的图）。**模型指纹与能量图景这两张卡不带 PNG 按钮** —— 它们要留存的是
  数不是图（卡片上那行读数、以及接口返回的 JSON）。

界面是**手写的仪器面板风**（**没有 CDN、没有框架**，全部离线可用）：一层网格底纹、
一层慢慢漂移的**节点网络**和一层次第闪烁的**星光**（都在 `web/backdrop.js` ——
节点加连线正好是这个软件自己的视觉隐喻，星是它的「远景」）、半透明的玻璃面板、
面板四角的边角标、青紫渐变的强调色。

两件事和以前不一样：

- **默认深色**。默认值写在 `<html data-theme="dark">` 上，所以**首帧就是深色**，
  不会先闪一下浅色底再翻过去；用户在右上角「深色/浅色」按钮上的选择记在
  `localStorage`，下次打开照旧。<html> 上那个属性删掉，页面就退回「跟随系统」。
- **通栏自适应，两侧不留空**。页面**没有 `max-width`**：正文宽度就是「视口减去
  164px 的 rail 和一个随视口走的 `--gutter`」，宽出来的部分直接分给图表和统计卡。
  成组的卡片（Kuhn 预置 ‖ h → n 反解）在 ≥1100px 才并排，不够宽就自己落成一列；
  七张统计卡用 `auto-fit` 排，一行排不下时不会在右端留下空轨道。

**每张图按自己 viewBox 的比例定宽，卡片跟着内容收窄**：缩放到 1:1 就是它的原始设计
尺寸，窗口窄了等比缩小、宽了不再长个儿，居中摆。上限逐张写：P(h) 与力–伸长 860、
链长扫描 1240、指纹那两张各 600、能量图景的四张 900 / 880。卡片宽度就是
**最宽那张图 + 两边各 20px 内边距** —— `#ph-card` / `#chain-card` / `#force-card` 900、
`#sweep-card` 1280、`#fingerprint-card` 1300（两张 600 并排）、`#energy-card` 1840。
窄于**两栏断点 2000px**（`.layout` 那条）时卡片跟着收到单张图的宽度，指纹卡与能量卡
各有一条 `@media (max-width: 1999px)` —— 这条断点必须与 `.layout` 那一条**同一个数**：
曾经写成 1499，于是 1500～1999px 这一段卡片还按两栏撑着、而里面的图已经竖着叠了，
每张右边空出近 660px。「标度验证」那一节自身要到 **≥2800px** 才排两栏
（(W − 230) / 2 ≈ 1280）。

**竖向间距 2026-09-29 收紧了一档**：卡片内边距、分区间距、标题与图之间的空档一起收，
1440px 下整页短 389px（6516 → 6127，6.0%）。收的**只有竖向** —— 左右内边距一个都没动，
上面那两条算式（卡宽度 = 图宽 + 两边各 20px、两栏断点 ≈ 2000px）钉着它们，动一个
两条注释同时失真；字号也一律不动，SVG 刻度、图注、图例吃的是可读性不是留白。

样式里是**三层 token，各管各的**：

| token | 管什么 | 谁在读 |
|---|---|---|
| `--series-1..5` | 数据色，**一个字都不能改** | 四张 SVG 图、3D 画布、图例、表格行标 |
| `--md-*` | 界面角色（primary / container / outline / state） | 控件长相 |
| `--accent* / --fill* / --hud-* / --net-* / --star-* / --panel*` | 外壳的装饰层 | 底纹、节点网络、星光、边框发光、大数字渐变、卡片标题 |

主色从墨色换成了青紫渐变，但「颜色只用来表示数据系列」这条没破：曲线一律穿
`--series-*`、装饰一律穿 `--accent*`，没有一处混用；填充面上压的白字逐个量过
对比度（浅色 6.08 / 8.98、深色 5.36 / 7.10，都过 4.5:1），亮青只做描边、聚焦环和发光。
正文那三级字色（primary / secondary / muted）也**都不是中性黑灰**，而是偏冷的深青蓝。

## 3D 单链构象（一次实现）

页面右侧是**另一件事**：按所选模型采样，真的走一条链出来 —— 从原点出发，
每一步走一个长度为 l 的矢量，方向由该模型定（自由连接链球面均匀、自由旋转链与
受阻旋转链固定键角、蠕虫状链按弯曲刚度、自回避行走在格点上且不重复访问格点），
累积即得轨迹。

左边 P(h) 画的是**系综平均**，右边画的是**一次随机实现**。单条链的 R 偏离
h_rms 是正常涨落，不是错误：只有多条链的 ⟨R²⟩ 才收敛到 n·l²。把两者并排，
正是这个工具最想讲的一点。

对照条会直接给出实测 R、理论 h_rms，以及**偏差**和它该有的量级。k 条链的
⟨R²⟩ 相对标准误是

> √(2/3) / √k

（由高斯链的 ⟨R⁴⟩ = (5/3)⟨R²⟩² 推出 Var(R²) = (2/3)(nl²)²）。k=1 时固有
涨落就有 ±81.6%，k=5 时还有 ±36.5% —— 所以「偏差 −20%」通常是完全正常的，
对照条会把它和该有的散布范围一起写出来。

交互：拖动旋转 · 滚轮缩放 · 双击或按 `0` 复位 · 聚焦后方向键旋转、`+`/`-` 缩放。
另外可以叠加多条链（最多 5 条，第 i 条用第 i 个系列色槽）、播放链生长动画、
导出 PNG / 坐标 CSV。页面上另有四个显示开关（坐标框 / 参考球 / Kuhn 刻度 / 读数），以及「跟随上面的参数」—— 勾上时链段数取顶部参数行的第一个 n、画几条链取 n 的个数（夹到 1–5），超过 20000 的绘制上限就不跟，并在卡片里说明原因。

「导出坐标 CSV」把**每条链的每个顶点**写成一行，列是

```
chain,segment,x,y,z,dx,dy,dz,s,r
```

前五列（`chain,segment,x,y,z`）与初版一致，后面四组是后来追加的，所以按老格式写的
读取脚本不会被这次改动弄坏。四组新列的意思：

| 列 | 含义 |
| --- | --- |
| `dx,dy,dz` | **到达**该顶点的键矢量（`p_i − p_{i−1}`）。第 0 行是原点、没有入边，留空 |
| `s` | 累计轮廓长度 = `i·l`（四个模型的每段长度都恰好是 `l`，所以直接乘，不逐段累加） |
| `r` | 该顶点到原点的直线距离 `\|r_i\|`（小写，与整链的末端矢量 `R` 区分） |

文件开头三行 `#` 是纯 ASCII 的注释头，记着模型 key 与 `n / l / seed / chains / b`，
以及**该模型真正在用的**那几个参数（自由连接链没有、自由旋转链有 `theta_deg`、
受阻旋转链有 `theta_deg` 与 `cos_phi`、蠕虫状链有 `p`）—— 这一份「谁用哪些参数」
直接取自 `/api/models` 的目录，不在前端另抄一份。注释头只能是 ASCII：文件按既定选择
**不加 BOM**，而不带 BOM 的 UTF-8 中文在 Excel 里会按本地代码页解成乱码。
文件名同样带上模型与 `l`（`fjc-chain-<model>-n<n>-l<l>-seed<seed>.csv`），
PNG 导出共用这个命名。

> **单位球面上的均匀方向**是 `z ~ U(−1,1)` + `φ ~ U(0,2π)`，**不是**「θ、φ 都均匀」。
> 后者会让方向往两极堆积，把 ⟨u_z²⟩ 从 1/3 抬到 1/2，链会系统性变形。
> `test_directions_uniform_on_sphere` 专门盯这条。

**模型下拉里选中「自回避行走（SAW）」**时，这块画布换成**两团并排**的链：
左边是同 n 的理想链、右边是格点上的自回避行走，两半**共用一套相机**（同一个包围盒、
同一个投影），所以两边的大小差别就是构象差别本身，不是缩放造成的。

（这里原来是一个独立的「自回避对照」复选框，已经删掉了：两个入口各说各话 ——
选了蠕虫状链还能勾「自回避对照」，画布上画的和顶部参数说的不是一回事。
现在模式跟着模型走，判据是目录里的 `analytic` 位，不在前端另写一份
「哪个模型是 SAW」。）

每边叠画 **20 条**独立实现，而不是各画一条。原因是单条链的 R² 涨落极大 ——
n = 30 时 `std(R²)/⟨R²⟩ ≈ 0.69`，比溶胀比本身（约 2.0）还大，各画一条的话
这一对有一小半时间会把结论反过来；那是涨落不是模型。叠成两团以后，眼睛看到的是
两边的**尺度差**，而底下的 ⟨R²⟩ 就是这 20 条的平均。两团各自给 ⟨R²⟩ 与这一条的 R，
SAW 那侧还写着溶胀比。

这一模式下坐标 CSV 会置灰（它导的是上面那条链的顶点，而画布上是这两团格点链），
PNG 照常，文件名里的模型 key 变成 `saw`。
n 借用 3D 卡自己的 n 栏，超过 30 会被夹到 30 并**在卡片上写明夹过**
（「自回避一侧的 n 已按算力上限夹到 30（你填的是 X）」）—— 不静默夹取。
为什么是 30，见下面「自回避行走」那节。

## 链长扫描：⟨R²⟩ 随 n 怎么长

页面底部是第三件事：把「⟨h²⟩ = n·l²」从一条公式变成一条**可验证的标度律**。
扫一组 n（最多 20 个），每个 n 采 M 条**独立**链，再对 log⟨R²⟩ 与 log n 做最小二乘拟合。
双对数坐标下 n·l² 恰好是一条斜率 1 的直线，所以「线直不直、斜率是不是 1」就是这条
公式的数值证据。默认 6 个 n、每个 10000 条链，约 4 秒；不点「运行模拟」就不会算。

图上除了模拟点（第 1 系列色）和理论线（第 2 系列色），还有：

- **拟合直线**（虚线）。斜率写进图例 —— 它和理论线在图上几乎完全重合，那正是要展示的
  结论，所以没法各贴一个直接标注，只给理论线贴一个。
- **±2σ 涨落带**。这是 M 条链的**有限样本涨落**该有多大，不是误差棒：⟨R²⟩ 的相对标准误
  是 √(2/3)/√M（M=10000 时 0.82%）。点落在带里说明采样器忠实于模型，落在带外才值得追。

**斜率的不确定度不等于单个点的不确定度。** 最小二乘下

> SE(slope) = rel_se / √Σ(ln nᵢ − mean(ln n))²

n 排得越开，斜率越稳。10 … 3000 这六个点的分母是 4.80，斜率的标准误只有 rel_se 的
1/5；只填 300 和 400 时分母只有 0.20，反而大五倍。汇总行会把这条标准误列出来，
后端判「斜率是不是 1」用的也是它（超过 3σ 才报警）—— 拿 rel_se 当门槛两头都错：
铺开的序列太松（真偏出 5σ 也不报），挤在一起的又太紧（把正常涨落冤枉成错误）。

> 只有两个 n 时任何两点都共线，R² 必然是 1，它在这里说明不了什么，页面会直说这一点。

导出两个：**汇总 CSV**（每个 n 一行，全精度）和**完整 JSON**（含请求参数、拟合结果、
全部逐点数据）。和 3D 卡片一样，这两个动作由用户点按钮触发。

扫描不占绘制预算，也不敢占 CPU：n ≤ 20、链数 ≤ 100000、Σ(链数×n) ≤ 60M（约 4 秒）。
它是**顶点无关**的 —— 只累加末端矢量、不存顶点，所以内存是 O(链数) 而与 n 无关；
这正是它能一次采上万条链、而 3D 视图最多只能画 5 条的原因。

## 自回避行走：另一种标度律

上面那条斜率 1 的直线说的是**理想链** —— 允许回头、允许自己穿过自己。真实的聚合物链
不能：同一个格点不能访问两次。加上这一条约束就是**自回避行走**（SAW），
而它换掉的是整条标度律。

另外四个模型的 ⟨h²⟩ 都来自同一个闭式解（`model_h2()`，一处供货），SAW **没有闭式解** ——
不是「还没推出来」，而是它属于另一个普适类：

> ⟨R²⟩ ∝ n^(2ν)，ν = 0.5875970（3D 立方格），2ν = 1.175194

这个指数由数值方法与共形自举定出，是这一节唯一的理论锚点。正因为没有闭式解，
**SAW 进不了 `MODEL_KEYS`**（仍是四项）：一旦进去，力曲线、反解、指纹、目录、AI 工具
全都要长出「本模型无解析式、不适用」的分支，四个解析模型的公式层就被污染了。
但它是用户能选的模型，所以它出现在**同一份模型目录**里（`/api/models` 的第五项），
只是带上 `analytic: false` 这一位 —— 前端只读这一位决定哪些卡片收起来，
不在各模块里各写一遍「哪个模型是 SAW」。它自带理想链对照，于是扫描卡里的
「验证斜率是不是 1」在这里变成「实测 ν 是不是 0.588」。

格点约定：立方格、6 个单位方向、步长 = `l` = 格点常数。同格点上的理想链（每步 6 选 1、
不管走没走过）⟨R²⟩ = n·l² 精确成立，与 FJC 恒等 —— 两者的唯一差别就是那条排除约束，
这正是卡片要展示的东西。

### 采样器必须是拒绝采样

有两条路，只有一条是对的：

- **均匀 6 选 1，撞上自己就整条丢弃**（带提前剪枝）。严格无偏，存活率恰好是 c_n/6^n
  （c_n = n 步一步自回避行走的条数，立方格上就是 OEIS A001412）。
- **只在空闲邻居里均匀选**。这是 Rosenbluth 采样：几乎不会死（6 个邻居全被占才死），
  但**有偏** —— 它给每条成功路径的权重不一样，⟨R²⟩ 会被系统性带偏。
  这个坑的样子很显眼：每个 n 的存活率都恰好是 1.00000。

第一版就是后者，是看到存活率恒为 1 才发现不对的。所以「存活率 = c_n/6^n」不只是个
好看的读数，它是采样器有没有退化成 Rosenbluth 的**判据**：内核里有一张 n ≤ 8 的精确
c_n 表，`test_fjc_core.py` 里那条测试用**现场 DFS 枚举**把它逐项钉住，再验实测存活率
（不是拿硬编码常数去比）。n ≤ 8 是有意的 —— n=9 的枚举要上千万次访问，测试跑不动，
而收进来的未验证常量比少一点精度更糟。

### 代价：n ≤ 30 是算力限制

存活率每加一步大约乘 0.78（渐近到 μ/6 = 0.7807，μ ≈ 4.684 是立方格的连接常数），
所以代价随 n **指数**增长：**n=30 比 n=10 贵约 250 倍**，n=40 要几分钟。
30 这个上限定死在这里，是**算力**限制不是物理限制 —— `SAW_N_MAX` 可以传 `None` 关掉，
和绘制预算、扫描预算一个路子。默认那组 n（5, 8, 12, 16, 20, 25, 30）每个采 1000 条链，
实测试投数从 n=5 的 2322 涨到 n=30 的 844632，整轮约 1~4 秒
（冷启动第一次约 4.2 秒，之后 1~3 秒）。

### 实测：这片 n 区间偏高，如实写出来

| 量 | 实测（默认参数，seed 2026） |
|---|---|
| 拟合斜率 | 1.2222 ± 0.0122 |
| 有效 ν = 斜率/2 | 0.6111 |
| 拟合 R² | 0.99964 |
| 溶胀 ⟨R²⟩/(n·l²) | 1.400 (n=5) → 2.082 (n=30) |
| 逐点相对标准误 | 0.017 ~ 0.022 |

**斜率落在 2ν 附近而不是 1 附近**，这就是结论。但它是**高于** 2ν 的：有限尺寸修正在
这个窗口的符号是正的，n 越小偏得越多。换一组种子斜率在 1.19~1.23 之间（20 个种子的
均值 1.2085）；把窗口挪到 n = 16~30，斜率为 1.1488 ± 0.0444，与 2ν 在 0.6σ 内相符 ——
但那个窗口只有 4 个点、标准误 0.044，分辨不出 1.15 和 1.176。

所以汇总行、图下的说明和导出的 JSON 里写的都是「实测偏高、这片区间**不能承诺 1.176**」，
而不是拿 2ν 去凑。图上两条参考线（斜率 1 的理想链、斜率 2ν 的文献值）都**锚在数据质心**上 ——
只有斜率是外部信息，振幅一个都不引。顺带一个诚实说明：**拟合线和 2ν 线在图上是分不出来的**
（斜率只差 1.6%），所以判据是汇总行里那个 σ 数，不是眼睛。

后端只在「**全是 n ≥ 10** 且斜率仍高出 2ν 三个标准误」时才报黄条 —— 带了小 n 的点时
偏高本来就是正常结果（实测能到 5σ），那时 3σ 这条既不是异常信号、又和「有 n < 10 的
点会把斜率推高」那条说同一件事，默认参数一跑就弹两条黄条反而像出了故障。

### 不确定度用的是实测值

`sweep()` 是**顶点无关**的，手上没有单条链的 R²，只能用高斯公式 √(2/3)/√M。
SAW 采样器手上就有每条链的 R²，所以 `rel_se` 是**实测的** std/√M —— SAW 的 R² 分布
比高斯窄（实测 std/⟨R²⟩ ≈ 0.5~0.63 对高斯的 0.816），套高斯公式会把误差报大约 40%。
各点的 rel_se 并不相同，所以斜率的标准误按**逐点传播**：

> Var(slope) = Σ (ln nᵢ − mean(ln n))² σᵢ² / Sxx²

各点误差相同时它才退化成扫描卡那条 σ/√Sxx（测试里钉了这条退化）。这条标准误是**可信**的：
20 个种子的斜率实测标准差 0.01138，而报出来的 slope_se 平均 0.01212（比值 0.94）。

### 预算与导出

n ≤ 30、每个 n 的链数 ≤ 20000，另有单点试投上限与整次扫描的共享试投总上限
（估算超了就 400 中文报错）。单点自己的试投上限兜住时**返回更少的链 + 一条点名是哪个 n
的 warning**，不静默少给、也不报错。

导出两个：**汇总 CSV**（每个 n 一行，比扫描卡多 `R2_2nu` 与 `h_rms_ideal` 两列）和
**完整 JSON**（含格点/方向/步长/采样器的元信息、拟合结果，以及有限尺寸那条注意事项）。
和别的卡片一样，两个动作都由用户点按钮触发。

## 四个链模型（FJC 和它的三个邻居）

「输入 n 得到 h」这件事，四个模型的差别只有两处：**等价 Kuhn 长度 b 是多少**，
以及**短链端怎么过渡**。长链极限下它们都回到同一条 ⟨h²⟩ = L·b（L = n·l 是轮廓长度）。

| 模型 | 加上的约束 | ⟨h²⟩ | 特征比 / 备注 |
|---|---|---|---|
| 自由连接链 FJC | 无 | n·l² | Cn ≡ 1，精确 |
| 自由旋转链 FRC | 键角固定、绕键自由旋转 | n·l²·Cn 的**有限 n 精确离散式** | 长链极限 Cn = (1−cosθ)/(1+cosθ)；θ=90° 退回 FJC、聚乙烯 109.47° → 2 |
| 受阻旋转链 | 再加内旋转势垒 ⟨cosφ⟩ | 再乘 (1+⟨cosφ⟩)/(1−⟨cosφ⟩)（长链极限） | 聚乙烯 θ=109.47°、⟨cosφ⟩≈0.5 → C∞ = 6（实测 C∞ ≈ 6.7） |
| 蠕虫状链 WLC | 连续杆状链，用持久长度 p | 2pL[1−(p/L)(1−e^(−L/p))]，b = 2p | 短链端退化成刚杆 L²，长链端才回到 L¹ |

三个参数：**键角 θ**（化学意义上的 ∠C–C–C，默认 109.47°）、
**内旋转平均余弦 ⟨cosφ⟩**（0 就是自由旋转链，聚乙烯约 0.5）、
**持久长度 p**（单位是 l，Kuhn 长度 b = 2p）。都在「链模型」那张卡片上，
**按模型显隐**：自由连接链三项都不显示，自由旋转链只显示 θ，受阻旋转链显示 θ 与 ⟨cosφ⟩，
蠕虫状链只显示 p，自回避行走一项都不显示（它在格点上走，这三样都不吃）。
显隐靠 `syncModelFields()` 设 `hidden`，配一条 `.field[hidden] { display: none }` ——
`.field` 是 `display:flex`，会盖掉 `[hidden]`，少了那条三个框会一直挂在卡片上。

切换模型以后，那七个统计量、P(h) 曲线、3D 单链构象、链长扫描、数值表**全都跟着换** ——
3D 那条链是按模型真的走出来的（固定键角 / 三态二面角 / 弯曲刚度），不是换个数字。

（下拉里的第五项**自回避行走**不在这四条之列：它没有闭式 ⟨h²⟩，上表里那一列对它没有意义，
所以它在目录里带 `analytic: false`，选中时上面这些跟着换的东西会**整块收起来**、
换成它自己的卡片。见「自回避行走」一节。）

三件**故意做成近似**、界面上也写明的事：

- **分布形状一律用等效高斯链**（只把 ⟨h²⟩ 换成当前模型的值）。前三个模型的 ⟨h²⟩ 是精确的，
  分布形状要等效 Kuhn 段数 L/b ≳ 10 才可靠，不够时页面会黄条提示。回转半径 Rg = √(⟨h²⟩/6)
  同理是等效高斯链的关系（刚杆极限会偏大 √2）。
- **受阻旋转链用的是经典近似**（⟨h²⟩ 只依赖 ⟨cosφ⟩，假设内旋转彼此独立）；严格做法是
  旋转异构态（RIS）矩阵，那是另一层。3D 采样用一个平均余弦一致的三态分布 ——
  任何同均值的独立分布给出同一条 ⟨h²⟩，但构象细节不同。
- **力–伸长曲线只有 FJC 的解**（Langevin），不随模型选择变化：另外三个模型没有同等地位的
  解析关系（WLC 的 Marko–Siggia 也是插值式近似），所以没混进来。

> 教科书的 (1−cosθ)/(1+cosθ) 是 **n → ∞** 的极限。工具里的统计量用的是有限 n 的**精确
> 离散式**（两重求和写成闭式），与渐近式差一个 O(1/n) 的常数项：聚乙烯、n=100 时 Cn 是
> 1.985（渐近式给 2.000）、受阻旋转链是 5.745（渐近式给 6.000）。差这一点的理由很实际 ——
> 采样器实现的是**有限 n 的离散链**，理论要是不同它对齐，「模拟 vs 理论」那张对照图会把
> 正常的物理差当成 bug（实测能把拟合斜率推到 1.09）。`freerotating_h2()` 保留渐近式，
> 专门给「θ=90° 与 FJC 精确相等」那条交叉验证用。

## 能量图景：只有两个模型画得出来

标度验证那节末尾那张「能量图景」卡**按模型显隐**，四个模型里只有两个有真正的
**能量自由度**：

| 模型 | 能量自由度 | 画什么 |
|---|---|---|
| 自由连接链 | 没有。除固定键长外没有约束，链段取向各向同性、彼此独立 —— 等价于势能恒为 0 | 不画（卡片收起） |
| 自由旋转链 | 没有。键角是**硬约束**不是势，绕键的旋转完全自由 | 不画（卡片收起） |
| 受阻旋转链 | **有**。内旋转势垒：trans(0°) 与 gauche±(±120°) 的能量不同 | U(φ) 势曲线 + 三态布居；Cn 随位垒 |
| 蠕虫状链 | **有**。弯曲刚度 κ：相邻键对齐与否能量不同 | 弯曲势 + 键角余弦分布；持久长度随弯曲刚度 |

对前两个不给硬凑一张图：没有势可画，画出来不是平线就是一个 δ 峰（自由旋转链的键角
是钉死的），零信息。卡片收起是**不取数**，不是取回来再藏起来 —— `energy.js` 的
`load()` 先看当前模型，不是那两个就直接返回（与指纹卡对自回避行走那条守卫同一条规矩）。

**两条式子都是精确的，不是拟合：**

- **受阻旋转链**。内旋转的 `⟨cosφ⟩` 换成能量语言：设 σ 为**单个** gauche 态相对 trans
  的玻尔兹曼因子，则

  > σ = (1 − c)/(1 + 2c)，ΔE/kT = ln(1/σ) = ln((1+2c)/(1−c))，c ≡ ⟨cosφ⟩

  这里算出来的 `p_trans = 1/(1+2σ)` 与采样器 `_torsion_steps()` 用的 `(2c+1)/3`
  **代数恒等**（测试逐点对拍）—— 图上画的就是采样器真正在抽的那个分布。
  `c = 0.5`（聚乙烯）⇒ σ = 1/4 ⇒ **ΔE = ln 4 = 1.3863 kT**，正是经典位阻因子 4，
  此时 Cn → 6；`c = 0` ⇒ ΔE = 0 ⇒ 三态等权重 ⇒ **精确退回自由旋转链**（两条闭式
  在这一格给出同一个浮点数，测试用 `assertEqual` 钉着）；`c = −0.5` ⇒ σ = ∞ ⇒
  **ΔE = −∞**（全部链段走 gauche），Cn 落到下界 Cn_FRC/3。
- **蠕虫状链**。采样器抽的 `p(x) ∝ e^(κx)` 就是势 `U(cosθ)/kT = κ(1 − cosθ)` 的
  **玻尔兹曼分布**（x = cosθ ∈ [−1,1]，势的值域 0…2κ）。κ 由 `L(κ) = e^(−l/p)` 解出，
  所以 `⟨cosθ⟩ = L(κ) = e^(−l/p)` 是构造出来的恒等式 —— 与模型指纹卡的 `corr[1]`
  是同一个数，同页两处能对上。`p/l = 10` ⇒ κ ≈ 10.508；大 `p/l` 端

  > κ ≈ p/l + 1/2

  （p/l = 100 时相对误差 8×10⁻⁶）。`κ → 0` ⇒ 键角分布变均匀 ⇒ 退回自由连接链。

**几处如实写明的事**（都印在图注或读数里）：

- **分布是离散的，势画成了一条曲线 —— 两张图画的是两件事。** 采样器只抽
  `{0, ±120°}` 三个**离散**值（三态模型），所以布居那张照旧是三根柱、不是光滑的
  三峰曲线。左边那条 `U(φ)` 画的是**势**：一口三井势，井底**正好**落在采样器抽的
  那三个 φ 上（曲线上那三个点就是），两个井底的高度差就是 ΔE。势说的是「这三个态
  为什么长这样」，它**不改变采样器的任何一个数**。
- **井底位置与井深是模型的，势垒多高是画法的约定。** 模型只给了一个数 ΔE（由
  `⟨cosφ⟩` 精确换算，`hindered_barrier()` 一处供货）；要画一条曲线还得另外定它多高。
  本图按 `TORSION_BARRIER_RATIO = 4` 取「**两个 gauche 井之间** = `4|ΔE|`」——
  基准放在那一处，是因为它连接的是**两个等价的井**，「比更高的那个井高多少」在那里
  没有歧义；trans↔gauche 那处连接的两个井不等高（相差 ΔE），基准本身就得再约定一次。
  换个约定曲线会变高变矮，**三个井底一动不动**。那个绝对值也是必需的：`⟨cosφ⟩ < 0`
  时 gauche 比 trans 低、井深差是负的，而势垒高度不能跟着变负，否则 0°/±120° 会从
  极小点翻成极大点、井底就跑掉了。旁证：聚乙烯（ΔE = ln 4）由此得
  `B_gg = 5.545 kT = 13.7 kJ/mol`，与聚乙烯真实的内旋转势垒（约 3 kcal/mol ≈
  12.6 kJ/mol）同量级。
- 一个**结构性推论**（不是选择）：trans↔gauche 那条势垒**总**比 gauche↔gauche 那条
  低（ΔE > 0 时实测 ≈ 3.68|ΔE| 对 4|ΔE|），这个差由 α 唯一决定、换任何形状参数都
  消不掉。所以这条曲线**不是 120° 周期的**：井底间距 120°、三口井一样深，但两条势垒
  不一样高，而 120° 周期会强制它们一样高 —— 整条曲线是 **360° 周期**的。
  只有 gauche↔gauche 那条有精确值 `4|ΔE|`（它是构造出来的）；trans↔gauche 那条的
  顶点是超越方程 `−α(sinφ + sin2φ) = 3a₃sin3φ` 的根，没有闭式，所以那个数由后端
  **从画出来的曲线上直接量**，读数与图必然一致（测试钉这一条）。
- **对那条连续曲线做玻尔兹曼积分，得到的权重与三根柱不是同一个数。** 三态是**离散**
  近似；曲线说的是「ΔE 是从哪来的」，不是「采样器在按它抽」。所以图上**不画**连续分布。
- 文献里常把 trans 画在 180°、gauche 画在 ±60°，与本项目的 0°/±120° 只差一个
  180° 平移，是同一个东西。
- **第 1 个二面角在采样器里没有参考平面**（只有一条链段时它没有定义），取的是均匀分布
  —— 所以图上是**模型定义**，不是从某次采样统计出来的直方图。
- `⟨cosφ⟩ = −0.5` 那端的 ΔE 真的是 −∞，但图画不出来：曲线截断在 −3 kT（那里 Cn 与
  下界只差 0.3%），虚实线标「ΔE = −∞」、当前点画在左边界。**方向仍然是对的**：
  0° 那个井被抬到两个 gauche 井上面（不是把整条曲线翻过来 —— 三个极小点位置一个不动）。
  这一端的两个势垒数建在截断值上（`B_gg` = 4×3 = 12 kT），读数行里注明，别让它看着像真值。
  JSON 里无穷一律写成 `null` 加一个 `all_gauche` 布尔 —— `json.dumps` 会输出
  `-Infinity`，而 JS 的 `JSON.parse` 直接报错。

卡片上那行读数是位垒 ΔE / gauche : trans / trans 占比 / Cn（受阻旋转链），
或 κ / 相邻键对齐的收益 / ⟨cosθ⟩ / 持久长度（蠕虫状链）。这张卡与模型指纹卡一样
**不带 PNG 按钮**：要留存的是数不是图。位垒同时也写进了「链模型」卡上那句模型说明
（`model_note()`），两个入口共用 `hindered_barrier()` 同一份换算。

## 接口

```
POST /api/compute
{"n": 100, "l": 1.0}
{"n": [10, 100, 1000], "l": 1.0}   // 最多 5 个

POST /api/chain
{"n": 1000, "l": 1.0, "seed": 12345, "chains": 1}

POST /api/sweep
{"n": [10, 30, 100, 300, 1000, 3000], "l": 1.0, "seed": 2026, "chains": 10000}

POST /api/saw/chain
{"n": 20, "l": 1.0, "seed": 12345, "chains": 3}

POST /api/saw/sweep
{"n": [5, 8, 12, 16, 20, 25, 30], "chains": 1000}

POST /api/force
{"n": 100, "l": 1.0, "x_max": 10, "temperature": 298.15}

POST /api/solve_n
{"h": 37.0, "l": 1.0, "kind": "h_rms"}     // kind: h_rms | h_mean | h_mp | h_max

GET  /api/kuhn      // Kuhn 长度预置表（唯一的那份在 fjc_core.KUHN_PRESETS）

GET  /api/models    // 链模型目录，唯一的那份在 fjc_core.model_catalog()
                    // 五项：四个解析模型 + 自回避行走，每项带 analytic 位

POST /api/model-curves
{"model": "frc", "theta_deg": 109.47}   // 模型指纹：Cn 随 n 的曲线（纯理论，不采样）

POST /api/energy
{"model": "hindered", "theta_deg": 109.47, "cos_phi": 0.5}
                    // 能量图景：受阻旋转链给三态位垒与 Cn–位垒曲线，
                    // 蠕虫状链给弯曲势、键角余弦分布与持久长度–刚度曲线，
                    // 其余两个模型返回 kind="none" 加一句中文理由
```

`/api/compute` 返回每个 n 的全部标量 + 400 点采样曲线（前端直接画，不再重算）。

`/api/chain` 返回这条链的顶点（每条链一段**扁平**数组 `[x0,y0,z0,x1,y1,z1,…]`，
4 位小数）、末端矢量 R、`R2_mean` / `R2_theory` / `R2_rel_se`。`seed` 传 null
时后端现取一个**并回传**，前端显示出来即可复现。

`/api/sweep` 返回每个 n 的 `R2_mean` / `R2_theory` / `rel_dev` / `Cn_sim`，加 `rel_se`、
拟合的 `slope` / `intercept` / `fit_r2` / `slope_se`，以及中文 `warnings`。
每个 n 用 `SeedSequence(seed).spawn(k)` 派生子种子，所以整条序列给定 seed 后可复现，
且**第 i 个位置的随机流只由 i 决定**，与序列长度无关 —— 往序列里加一个 n，不会打乱其余的点。

`/api/saw/chain` 返回 SAW 的 `chains` 条链与同 n、同样条数的理想链的顶点
（两边形状一致，直接并排叠画），外加 `R2_mean` / `R2_ideal` / **实测的** `R2_rel_se` /
`swelling` / `accept_rate` / `trials`。3D 卡固定要 20 条 —— 每边多画几条是为了压掉
单条链的 R² 涨落（见上面 3D 那一节），读数与画面上那两团因此始终是同一批链。
`/api/saw/sweep` 返回每个 n 的 `R2_mean` / `R2_ideal` / `swelling` / `rel_se` / `trials` /
`chains_used`，加拟合的 `slope` / `intercept` / `fit_r2` / `slope_se`，以及
`nu_eff`（= 斜率/2）、两条参考线 `intercept_ideal` / `slope_ref` + `intercept_ref`。
**这两个不收 `model` / `theta` / `cos_phi` / `p`** —— 自回避行走没有闭式 ⟨h²⟩，
不进那四个模型，多传的参数会被忽略而不是报错。

`/api/force` 返回 400 点的 `x`（无量纲力）、`λ`、绝对伸长、力（pN），
外加高斯对照线 `curve_linear`、λ 到达 `x_max` 的位置、两条线开始相差 2% 的 x。
**曲线本身与 n、l 无关**（Langevin 函数里根本没有它们）：`n` 是必填的
（走和主图同一套 `validate()`，所以单位、上限、错误文案都一致），但它和 `l`
只影响返回里的「绝对伸长」那一列，`temperature` 只影响 pN 那一列。
单位换算 `f[pN] = x·0.01380649·T/l_nm` 和它的精确线性逆都在后端，前端拿到什么读什么。

`/api/solve_n` 把末端距反解成链段数，`kind` 指明 `h` 是哪一种统计量
（`h_rms` / `h_mean` / `h_mp` / `h_max`），返回连续解 `n_exact` 与 ⌊n⌋、⌈n⌉
两侧整数解各自的 h。**必须说清是哪一种 h** —— h_rms 和 nl 在同一个 n 下差一到两个数量级。

`GET /api/kuhn` 返回那张 Kuhn 长度预置表，每条带 `conf_label` 可信度标签
（DNA 是硬值、聚乙烯由定义式 `b = a√C∞` 推出、其余标「文献标称值」）。
这张表**只是把 `l` 填到正确量级的一条捷径，不代替物性表**：
同一种聚合物的 b 在文献里能差一倍（温度、立构规整度、溶剂、以及作者给的到底是
b 还是持久长度 p）。

`GET /api/models` 返回模型目录，**这是「模型有哪些、各叫什么、每个模型用哪几个参数」
的唯一真源** —— 前端不抄第二份。每项带 `key` / `label` / `formula` / `note` /
`params`（每个参数带 `label` / `unit` / `default` / `min` / `max` / `used`）与
`analytic`。`analytic` 是这次新加的**第二类事实**：这个模型**有没有闭式 ⟨h²⟩**。
四个解析模型是 `true`，自回避行走是 `false` —— 前端只读这一位决定 P(h)、力–伸长、
h→n 反解、模型指纹、数值表、主结果大字这几块**显示还是收起**，
不在各模块里各写一遍 `if (model === 'saw')`。`params` 里三项对 SAW 全是 `used: false`
（格点上走，没有键角、没有内旋转、没有持久长度），但 `default` 照样给 ——
前端拿它做说明文案里的替换，缺了会抛。

`POST /api/model-curves` 给「模型指纹」那张卡供货：Cn 随 n 的曲线，**纯理论、不采样**。
它和 `/api/compute` 的区别就是这句话 —— 前者是闭式曲线，后者是采样统计。

`POST /api/energy` 给「能量图景」那张卡供货，同样**纯理论、不采样**，而且**前端一个
公式都不写**：U(φ) 势曲线、井深、两条势垒、布居、Cn 曲线、弯曲势、键角余弦密度、
κ 扫描与那条渐近线，全部在这里算好（唯一那份在 `fjc_core.energy_figure()`）。
回复按 `kind` 分三支：
`torsion`（受阻旋转链）、`bending`（蠕虫状链）、`none`（另外两个模型，附一句中文
`reason`）。受阻旋转链那支的无穷量写成 `null` 并另给 `all_gauche` —— 理由见上面
「能量图景」一节。

绘制预算（**表现层约束，不是物理约束**）：n ≤ 20000、链数 ≤ 5、
链数×(n+1) ≤ 60000。超出返回 400 和中文提示。这三个上限在
`validate_chain()` / `random_chain()` 里都是可以单独传 `None` 关掉的参数，
统计验证需要几千条链才能让 ⟨R²⟩ 收敛，超出绘制预算是故意的。

扫描预算同理（**计算量约束**）：n ≤ 20、链数 ≤ 100000、Σ(链数×n) ≤ 60M，
对应 `validate_sweep()` 的 `max_points` / `max_chains` / `work_max`，也都能传 `None`。

非法输入返回 400 和中文错误信息。

上面十一个是**无状态**的。AI 助手那五个路由里，`ask` / `resume` 是**有会话状态**的、
`status` / `config` / `test` 是配置读写，形状不一样，都放在下面的「AI 助手」一节里。

## AI 助手

页面**顶栏右上角**（「深色」按钮旁边）有个「AI 助手」按钮，点开是右侧抽屉。
它能调用这个软件的全部功能 —— 算统计量、对比多个 n、模拟单链、跑标度扫描，
也能直接改界面参数并把图重画。没配模型网关也能用（见下面的「本地模式」），配了就能自由对话。
**链模型是这版唯一的例外**：助手那 16 个工具仍然只算 FJC，页面上选的模型不会传给它
（下一步要么给工具加参数、要么让它先读页面状态）。

抽屉是**右侧固定 380px 的全高浮层**，不进两栏布局，所以现有的断点（1280px 两栏、
640px 单列）一个都没动；窗口 ≥960px 时打开抽屉会给页面让出右边缘，
免得盖住 3D 卡片右侧 —— 「改个参数、眼看图重画」正是最常用的用法。窄屏上占满全宽，Esc 关。

### 配一个模型网关（可选）

需要一个 **OpenAI 兼容**的 `chat/completions` 接口。三条路，**环境变量优先**。

**最省事的一条在页面上**：抽屉头部那个 ⚙（或页脚的「接入设置」）打开接入设置面板，
选服务商 → 填 endpoint / model / key → 「保存」。保存后**下一句提问即生效，不用重启**；
「测试连接」会拿当前（或表单里临时填的）三样发一次极小的请求，通了就报时延和模型名。
「清除密钥」只删 key，endpoint 和 model 保留，助手退回本地模式。

面板里那一栏有个讲究：**密钥框永远是空的**，已存的密钥只以末四位掩码的形式出现在
placeholder 里（`已保存 ••••1a2b　留空则不改`）。所以语义是——**留空＝不动**，
要改就打新的，要删就点「清除密钥」。这是故意的：掩码要是当值回填进去，
用户一进表单点保存就会把真 key 覆盖成 `••••1a2b`，而且不报任何错。

环境变量（cmd；PowerShell 里是 `$env:FJC_LLM_KEY="…"`）：

```bash
set FJC_LLM_KEY=sk-xxxxxxxx
set FJC_LLM_ENDPOINT=https://api.deepseek.com/v1
set FJC_LLM_MODEL=deepseek-chat
```

或者建一个 `ai_config.json`，放在 `server.py` 同目录（和这份 README 同级）：

```json
{
  "key": "sk-xxxxxxxx",
  "endpoint": "https://api.deepseek.com/v1",
  "model": "deepseek-chat"
}
```

**这个文件不在仓库里。** 页面点「保存」会替你建（写的是同目录的 `ai_config.json`），
手动建也行。字段可以只写一部分，缺的走默认：`model` 默认
`deepseek-chat`；`key` 和 `endpoint` 缺任何一个就算未配置（页面会显示「本地模式」）。
`"enabled": false` 或 `FJC_LLM_ENABLED=0` 显式关掉网关、强制本地模式。

手写这份文件时 `key` 是明文；**页面上保存的会换成 `key_dpapi` 密文**（见下）。
两种写法都认，文件里同时有这两个字段时以 `key_dpapi` 为准。

**endpoint 填 base 就行 —— 只往后接 `/chat/completions`，不替你猜 `/v1`。**
各家的 base 路径差别很大，硬补一个 `/v1` 会把前两家弄坏：

| 服务商 | endpoint | 常见 model |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 推理接入点 ID（`ep-…`） |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

这张表**不是手抄的第二份**：代码里的唯一来源是 `ai.PROVIDERS`，
`/api/ai/status` 的 `providers` 字段把整份表原样吐出来，页面上那个「选择服务商」下拉
就是照着它生成的。要加一家，改 `ai.PROVIDERS` 一处即可，表单和这行文档都跟着变。

已经填到 `/chat/completions` 结尾的完整地址也认，原样使用。

配置**每次调用重读** —— 文件很小，所以改完 `ai_config.json` 不用重启服务；
改环境变量要重启。文件坏掉（不存在 / 非法 JSON / 顶层不是对象 / 不是 UTF-8 / key 为空）
一律只是「未配置」，不抛异常，页面上会说清是哪种坏法。

**保存的三条讲究**（`ai.save_config()`）：

1. **只动 key / endpoint / model 三项**，文件里别的字段（比如你自己加的 `"enabled": false`）原样保留。
2. **先写 `ai_config.json.tmp` 再 `os.replace`** —— 写一半崩掉的 JSON 会被读成「未配置」，
   那就等于把用户刚填的 key 悄悄弄丢了；原子替换不会留这个窗口。正常结束时不留 `.tmp` 残骸。
3. **保存成功 ≠ 生效**：环境变量优先级更高。所以凡是被 `FJC_LLM_*` 压住的字段，
   返回值里会带 `warnings` 点名是哪几个 —— 否则会出现「填了、存了、但怎么还是老样子」。

**先验后写**：endpoint 必须是 `http://` / `https://` 开头，长度、类型也都有上限
（512 / 400 / 200 字）。不合法的请求在碰磁盘之前就被 400 挡下 ——
所以填错地址不会把一份好配置冲掉。

### 密钥在磁盘上是怎么存的

**页面上保存的密钥是加密的**，用的是 Windows 自带的 DPAPI
（`crypt32.CryptProtectData`，`ctypes` 直接调，**没有引入任何依赖**）。
存进去的是 `key_dpapi` 这个字段：

```json
{
  "key_dpapi": "AQAAANCMnd8BFdERjHoAwE/Cl+sBAAA…",
  "endpoint": "https://api.deepseek.com/v1",
  "model": "deepseek-chat"
}
```

密文**绑定当前 Windows 账户**：同一个文件拷到别的机器、别的账户底下就是一串解不开的字节。
这一条是冲着一件真事去的 —— 这份配置曾经连同两个 zip 一起被发出去过，谁下载谁就拿到一把
能直接花余额的钥匙（见 `CHANGELOG.md`）。清理历史只能防「这一份再出去」，
防不住「它已经出去了」：目录被拷走、换个方式打包、进备份、截图，穿过任何一样就没用了。
加密之后，漏出去的只是一串在别的机器上没用的字节。

**它挡什么、不挡什么** —— 这句别读成「密钥从此安全了」：

- **挡**：文件被拷到别处。换台机器、换个 Windows 账户、被打进包里发出去，都解不开。
- **不挡**：已经以你的身份在运行的程序。那种程序自己也能调 `CryptUnprotectData`，
  DPAPI 对它一点阻力都没有。上面「本机任意进程都能打到这些接口」那条代价**没有改变**。

**加不了密的时候会退回明文，并且明确告诉你。** 非 Windows、或者 `crypt32` 调不动的机器上，
保存仍然成功，但密钥是明文写在 `key` 里的，同时：

- 保存接口的返回里多一条 `warnings`，面板上会显示出来；
- 面板的密钥框下面那行小字会说「密钥是明文存的」；
- `GET /api/ai/status` 的 `key_storage` 字段是 `"plain"`（加密时是 `"dpapi"`，
  来自环境变量时是 `"env"`，没配则是 `null`）。

降级必须出声，是因为**用户以为自己受着保护、实际是明文，比一开始就知道没加密更糟** ——
前者会让人放心地把目录拷来拷去。

老文件里手写的明文 `key` 照常能读（只是标成 `"plain"`）；**服务启动时会顺手把它换成密文**
（`ai.migrate_config()`，只换存储方式、不动密钥本身，所以不用你重填，也不用重启）。
换过 Windows 账户或换过机器导致密文解不开时，服务**不会起不来**：要么退回文件里同时存在的
明文 `key`，要么在页面上说一句「请在接入设置里重填一次密钥」。
`server.py` 同目录如果还有 `ai_secret.py`，那是这套加密的实现，独立成文件是为了能被单独测试。

### 在页面上改，为什么当初说不行、后来又加了

这一节原来是「密钥不进浏览器」。**推翻它的是用户明确要求**（「做一个可以输入 api 接入的前端接口」，
三栏全可填），代价照实记在这里，不是忘了当初为什么那么写：

> 这个服务本地单用户、零认证，任何能访问这个端口的程序都能打到它的接口上。
> 加了写 key 的路由，等于**本机任意程序都能改掉你的 key、或把 endpoint 指到它挑的地方**
> —— 后者更阴：下一问会连同密钥一起发过去。换来的是不用碰文件、页面上直接改。

守着的几条：

- **响应体里永远没有 key 原文**，`status` 和 `save_config` 返回的都只有末四位掩码；
  连网关 401 时回显 key 的错误信息也会先 `scrub()` 洗掉再给前端。
- **密钥框从不回填**（见上一节），所以表单本身泄露不出东西。
- **助手（模型）改不了配置。** `saveSetup` / `testSetup` / `clearKey` 都不在 `ai_tools.TOOLS` 里、
  也不在 `ai.js` 的 `ACTIONS` 表里 —— 能改的话，一次提示注入（工具结果里塞一句话）
  就能把 endpoint 指到攻击者那边。`test_ai.py` 有一条断言专门盯着「配置表单进不了动作表」。
- **只收 `application/json`**（`get_json(silent=True)` 对表单 POST 返回 `None`，跨站表单打不进来），
  也不加任何 CORS 头 —— 跨站的 `fetch` 带 JSON 会先要一个我们不回答的预检。
- **没有认证、不打算加。** 往上加登录、多用户、远程访问，上面那句「代价」就会变成真问题，
  真到那时得重新设计，不是往这个口上补一层就完事。

真正要保护的不是数据而是**钱** —— 这个接口会去调付费网关。

> `ai_config.json` 里页面上保存的密钥是**加密的**（DPAPI，见上一节），但**别把它拷到别处去**
> —— 那份配置里还有 endpoint、model，而且密文只在这台机器、这个 Windows 账户下才解得开。
> 更别连着 key 一起截图发出去：DPAPI 保护的是文件，不是你的屏幕。

### 本地模式：没配 key 也能用

没配网关，或者网关超时 / 连不上 / 返回不可解析时，助手退到本地模式：按关键词认几种固定问法，
**答案里的数字全部来自同一批工具**（也就是 `fjc_core` 的计算内核），不是另写一套算式 ——
更不是模型随口说的。

能认的：

- `n=400 的 h_rms 是多少`
- `100 和 1000 比一下`
- `把 n 改成 400，并打开归一化显示`
- `画一条 n=500 的链`
- `扫一下 10 到 1000 的标度关系`
- `拉到 60% 需要多大力`
- `h=37 要多少个链段`
- `播放生长动画`

认不出的会**直说认不出**，并列出能干什么 —— **绝不猜数字**。`test_ai.py` 里专门有一组测试
盯着这条：本地模式下所有拒绝文案里出现的数字，必须全部来自那几条示例问法和工具清单，
出现任何别的数字就算测试失败。

已知的边界（不是没想到，是关键词匹配做不到）：一句话里「一半认得、一半认不得」时，
认不得的那半会被**安静地丢掉**，不会附上一段「这半句我没懂」。要判断哪半句属于谁，
得先切分句子，那是另一套东西。想自由对话就配网关。

### 它能做什么

16 个工具，分两类。

**算 —— 在本进程内直接调 `fjc_core`，不走 HTTP 回环**（自己请求自己会占住一个 worker，
还要处理端口，纯属自找麻烦）：

| 工具 | 回答什么问题 |
|---|---|
| `compute_statistics` | 某个 n 的全部统计量（h_rms / h\* / ⟨h⟩ / σ / Rg / nl / Cn），外加序关系自检 |
| `compare_n` | 多个 n 的同一张表，以及各自对第一个 n 的倍数 |
| `simulate_chain` | 随机走一条链会走多远、R 和 h_rms 差这么多正不正常 |
| `run_sweep` | ⟨h²⟩ = nl² 凭什么可信、标度律对不对 |
| `freerotating_check` | 换一个链模型（自由旋转链）结果一不一致 |
| `solve_n` | 「要 37 的末端距得多少段」—— 反过来由 h 求 n |
| `force_extension` | 「拉到 60% 要多大力」「0.5 pN 能拉多长」 |

`simulate_chain` **不返回顶点坐标**：顶点是给画布用的，n=1000 就是 40KB，
塞进对话上下文纯属浪费。要画图走下面的前端工具。

**操作界面 —— 由浏览器执行，走界面自己的那条路**（派发 `input`/`change` 或调它自己的刷新函数），
所以图会真的跟着重画，不是改个 DOM 值糊弄：

| 工具 | 落到哪 |
|---|---|
| `get_page_state` | 读当前界面状态（用户说「这个」「当前」时先调它，不猜） |
| `set_params` / `set_curves` / `set_normalize` | 顶部参数行、对比曲线集合、归一化开关 |
| `set_chain_params` / `set_chain_view` / `play_chain` | 3D 卡片的参数、视角、生长动画 |
| `set_sweep_params` / `run_sweep_view` | 扫描卡片的参数与「运行模拟」 |

助手**能先改参数再回答**：碰到前端工具会暂停，把待执行的动作交给浏览器，执行完再把
**真实结果**（包括界面报的中文错误）送回去让它接着说 —— 所以「把 n 改成 400」不会出现
「已改」而界面纹丝不动。前端动作最多连着执行 4 批，超了如实说停在这里。

扫描卡片是唯一一个「够不着接口」的：`sweep.js` 对外什么都不暴露，所以助手只能**走 DOM**
（填好输入框 → 点 `#s-run` → 等它自己把按钮解禁，最多等 60 秒）。页面上找不到那些控件时
如实回「扫描卡片暂不可用」，不假装改过了。

前端工具的实参**先按白名单清洗再落地**：不认识的键丢掉，`n` 必须是正整数，`chains` 1–5，
`zoom` 夹到 0.4–4，永远不 `eval`。助手正文一律 `textContent` —— 模型输出和用户输入都是
不可信内容，一次提示注入就能变成 HTML 注入，所以只做 `white-space: pre-wrap`，不解析 Markdown。
既然不解析，系统提示词里就明确告诉模型**别写 Markdown 记号**（它会原样显示成星号和井号）——
这两条是一对，`test_ai.py` 里各有一条测试盯着，改一边忘另一边会在测试里挂掉。

### 它不做什么

- **不导出。** PNG / CSV / 完整 JSON / 复制数值表**不是**助手的动作 —— 那几个会落盘或进剪贴板，
  仍然由你点按钮。助手知道它们存在，会说「点 3D 卡片上的 PNG 就能导出」，但不会替你按下。
  这条是产品决定，不是没来得及做。
- **不切主题。** 深浅色是显示偏好，助手替你翻是意外行为。
- **不落盘。** 对话历史只在内存里，刷新即清，不写进 `data/`。
- **不做流式输出**，用阶段提示（「正在计算…」「正在操作界面…」）代替，免得对话框像死了一样。
- **有硬上限**：一次问答最多 6 轮工具调用、单次 HTTP 20 秒超时、整体 60 秒墙钟预算，
  三者是「与」关系，谁先到谁收口，收口时会说明。会话 30 分钟没动静就丢，最多同时留 50 个，
  单个会话的消息上限 32 条（裁最旧的，系统提示词永远留着）。
- **助手这条路比按钮更省着用 CPU**：`run_sweep` 工具硬限制 `chains ≤ 2000`、
  `chains × Σn ≤ 12,000,000`（约 1 秒）、n 最多 8 个，比界面那条 60M 的预算紧得多 ——
  一个聊天问题不该占住 CPU 四秒。超了会**降到上限并在回复里说明**，不是静默截断。
  想跑大扫描请点界面上的「运行模拟」。

### 五个路由

```
GET  /api/ai/status            # 只读，给页面用
  -> {"enabled": true, "configured": true, "source": "env"|"file"|null,
      "endpoint": "...", "model": "...", "masked": "••••1a2b",
      "local_fallback": true, "max_rounds": 6, "note": "...",
      "providers": [{"name": "DeepSeek", "endpoint": "...", "model": "..."}, …]}
  # masked 是末四位掩码，原始 key 永不出现在任何响应里。
  # providers 就是「选择服务商」那个下拉的全部选项，来源 ai.PROVIDERS。

POST /api/ai/config            # 接入设置面板的「保存」「清除密钥」
  {"key"?: "...", "endpoint"?: "...", "model"?: "...", "clear_key"?: true}
  -> 与 status 同形，外加 "saved": true，可能带 "warnings": [...]
  # 字段语义（不传 = 不动）：
  #   key         ""  = 不动；非空 = 覆盖；clear_key: true = 删掉它
  #   endpoint    不传 = 不动；""   = 写空（等于删掉）
  #   model       不传 = 不动；""   = 写回默认 deepseek-chat
  # 只改这三项，别的字段原样保留；先写 .tmp 再 os.replace；不合法 → 400，不碰磁盘

POST /api/ai/test              # 「测试连接」
  {"key"?: "...", "endpoint"?: "...", "model"?: "..."}
  -> {"ok": true,  "ms": 123, "model": "...", "endpoint": ".../chat/completions", "reply": "…"}
  -> {"ok": false, "error": "...", "ms": ...}
  # 没传的字段用已保存的值；**不带 tools**（见下面的降级链，那是进程级记忆）
  # 三样不齐、或网关被显式关掉，直接说，不发请求

POST /api/ai/ask     {"message": "...", "session_id"?: "..."}
POST /api/ai/resume  {"session_id": "...", "results": [{"tool": "...", "ok": true, "data": {...}}]}

  -> {"session_id": "...", "status": "final", "answer": "...", "source": "llm"|"local",
      "steps": [{"tool": "compute_statistics", "args": {"n": 400}, "ok": true}],
      "degraded": null|"超时"}
  -> {"session_id": "...", "status": "actions", "actions": [{"tool": "...", "args": {...}}],
      "steps": [...]}
```

`config` 和 `test` 都只收 `application/json`，参数不合法（endpoint 不是 http(s)、字段超长、
类型不对）返回 **400 + 中文原因**，且**在写盘之前**就挡掉。

`status: "actions"` 就是上面说的「暂停等浏览器执行」那一档，`resume` 把执行结果送回去续跑。
`steps` 每一项是 `{tool, args, ok, deferred?}`：`deferred: true` 表示这条是**交给界面执行**的，
服务端并不知道成没成 —— 前端执行完会把 `ok` 校正过来再显示，所以「执行」那一行不会报喜不报忧。

**一轮停在半路也没关系。** 浏览器那侧有 4 批动作的上限，用户也随时可以点停止或关掉抽屉 ——
这时 `resume` 不会来了，会话里就留下一条「assistant 说要调工具、但结果没人送回」的记录。
下一次提问时，服务端会先给这轮**补一条「没有确认执行」的结果**再往下走，而不是把它删掉：
一来标准 function calling 要求两者成对出现，孤儿记录会让严格的网关直接 400
（表现成「上一轮只是停了一下，这一轮却报网关错误」，非常难查）；
二来补上结果比删掉更诚实，模型下一轮也因此知道界面其实没动过。

会话 id 不传就现开一个并回传，前端存着，下一句接上。会话之间互不串。

**网关失败时返回的是带了答复的 200**：`{"ok": false, "error": ..., "detail": ...}` 加一段
标明「本地模式（网关超时）」的兜底回答 —— 宁可显示「网关超时了，下面是本地模式按关键词算的
结果」，也不要把兜底结果伪装成模型回答。每条回答都带来源标签，就是干这个的。

### 网关不支持 function calling 时会降级

国内网关对 `tools` 的支持参差不齐，所以有一条四级降级链：

1. 带 `tools` 发请求，正常走 `tool_calls`
2. 没有 `tool_calls`，但**正文里**有一个像工具调用的 JSON 块 → 抠出来
   （形如 `{"tool": ..., "args": {...}}`，带代码围栏的、夹在散文里的、
   `arguments` 是字符串的，都认）
3. 都没有 → 当最终回答
4. 网关对带 `tools` 的请求直接 **400** → 去掉 `tools` 重试一次，之后本进程内不再发 `tools`

第 2 条能走通不是碰巧：工具说明在系统提示词里**也写了一份**。`ai_tools.py` 里每个工具
只定义一次，`openai_tools()` 和 `tools_prompt()` 是同一份定义的两个视图 ——
不是两套实现，所以不会写着写着就不一致了。

第 2 条路下工具结果是以**普通 user 消息**回灌的（不是 `role: "tool"`）—— 孤立无主的
`tool` 消息会让网关报 400。

### 不引入新依赖

传输用 stdlib 的 `urllib.request`，不用 `requests` / `httpx`：本机 anaconda 三个都有，
但上面那句「依赖只有 flask / numpy，不需要 pip 安装」得在裸 `python` 回退时也成立。
需求就是一次 POST 加一个 JSON body，urllib 够用。

**物理公式与链模拟都只在 `fjc_core.py` 一处**，前端不做任何计算，只负责格式化和画图。
归一化视图也只是一个显示变换（除以 h_rms、乘回 h_rms），不是第二套公式；
链模拟里 `random_chain()` 的理论量直接调用 `compute()`，标度扫描里 `sweep()` 的

纯函数，挂到 `window.fjcSweepHelpers` 上给 `saw.js` 取用。两张图是同规格的双对数图
（同一个 `viewBox`、同一套轴约定），刻度逻辑不该有第二个版本。

AI 助手也不构成第二套公式：`ai_tools.py` 里每个服务端工具都是去调这几个函数，
一行物理都没写；`test_ai.py` 有一组测试把这条钉死（工具的返回与 `compute()` 逐字段对拍）。

图表用 SVG 还是 canvas 有条现成的判断：**SVG 的 fill/stroke 认 CSS 变量**，所以
P(h) 和链长扫描两张图直接用 `stroke="var(--series-1)"`，深浅色切换自动跟上；
canvas 不参与 CSS 变量解析，3D 视图（**手写的 canvas 2D 正交投影**，没有引入 Three.js
—— 保住「无框架、无 CDN、离线可用」）每次重绘都得
`getComputedStyle(root).getPropertyValue('--series-1')` 现取，否则切换深浅色后
画布颜色不会跟着变。


两个文件加起来 **332 项**（`test_fjc_core` 166 + `test_ai` 166）。
**物理内核与 AI 助手是分开测的** —— AI 那一侧从头到尾只是**调** `fjc_core`，一行也不改它。

测试的核心手法是**解析式 vs scipy 数值积分**：∫P dh = 1、∫h²P dh = nl²、
⟨h⟩ 的解析值与数值积分一致、h* 处导数为 0。

另外两条交叉验证：

- **自由旋转链一致性**：⟨h²⟩ = nl²(1−cosθ)/(1+cosθ)，θ=90° 时退化为 nl²。
  代入聚乙烯键角 arccos(−1/3) 得 Cn = 2，正是教科书值。
- **标度塌缩**：上面那条与 n 无关的归一化恒等式，且该常数本身用
  ∫₀^∞ C·x²e^(−1.5x²)dx = 1 反验过。

链模拟这一侧验的是「采样器有没有忠实实现 FJC」，不是分布公式：

- **每段长度恰为 l**，方向在球面上均匀（⟨u_k²⟩ ≈ 1/3，专抓角度均匀那个坑）
- **系综收敛**：2000 条链的 ⟨R²⟩ 落在 n·l² 的 5% 内 —— 采样器忠实于模型的硬证据。
  seed 写死以保证确定性，否则会偶发失败
- **新代码钉在旧内核上**：`random_chain(n).R2_theory == compute(n).h2`
- 种子可复现、`seed=None` 回传可用、n=1 退化、随 l 线性缩放、非法输入全抛错

标度扫描这一侧验的是「标度律真的成立」，以及那条标度律的**不确定度别算错**：

- **斜率 ≈ 1**：六个跨两个半数量级的 n，容差 0.02（≈ 5σ，seed 写死否则会偶发失败）
- **Cn 不随 n 漂移**：每个 n 的 R2_mean/(n·l²) 都要落在各自的 3σ 内 ——
  专抓「标度律只在某一段成立」这类错（比如 n 大时方向分布走偏）
- **扫描和 3D 用的是同一个采样器**：同一条随机流上，`_sweep_endpoints` 与
  `random_chain` 的末端矢量**逐位相同**；分块累加与一次算完也逐位相同
- **斜率的标准误**：按上面那条式子逐位验过，并显式钉住「铺开的序列里 slope_se 比
  rel_se 小得多、挤在一起的反而大得多」。之前拿 `3·rel_se` 当门槛是错的：
  对 n=300/400 会误报（斜率 0.9149 看着离谱，其实离 1 不到一个它自己的 σ）
- 三个预算各自独立、都能传 `None` 关掉（用「把上限调小」触发，不真跑 7 秒）

自回避行走这一侧（`TestSaw`，19 项）和上面都不同：**没有解析式可以对照**。
所以「算得对不对」换了个独立来源 ——

- **精确 c_n 由测试现场 DFS 枚举**（不用魔法数字），核心里那张 n ≤ 8 的表逐项对着枚举校验。
  这是全套的依据：表错了，后面拿它当判据的测试就都成了自证
- **实测存活率 = c_n/6^n**（4σ 内）。这条专抓 Rosenbluth 那个坑 —— 采样器一旦退化成
  「只在空闲邻居里选」，存活率会变成 ~1，这条立刻炸
- **每条链逐点验证自回避**、步长恒为 `l`、每一步都落在格点上、首点是原点
- **理想链那一侧的 ⟨R²⟩ = n·l²** 落在它自己 √(2/3)/√M 的涨落里（理想链**就是**高斯链，
  高斯公式在这里用得上；SAW 那一侧反而不能用，见下）
- **溶胀是真的**：⟨R²⟩ 明显大于 n·l²，且随 n 单调变强（n=5 约 1.4 倍、n=30 约 2.1 倍）
- **rel_se 是实测的**，逐位等于 `std(R²)/⟨R²⟩/√M`，且**小于**高斯的 √(2/3)/√M ——
  这条是刻意钉住的：套高斯公式会把误差报大约 40%，那不是笔误
- **斜率标准误的逐点传播**：各点误差相同时必须退化成扫描卡那条 σ/√Sxx
- **参考线过数据质心**：两条线在 ln n 的均值处同时穿过 ln⟨R²⟩ 的均值（不引振幅）
- **不许承诺 1.176**：斜率必须显著 > 1、且落在 2ν 之上但不超过 5σ —— 把「这片区间偏高的
  有限尺寸修正」写成测试
- 可复现（同种子逐位相同、换种子必须不同）、超预算抛**中文** `FJCInputError`、
  `accept_rate` 按存活条数而不是返回条数算、批量不按内存上限整批投（用纯比值卡，不计时）

目录那一侧只钉一条（`test_model_catalog_is_json_safe`），但它钉的是**前后端之间的契约**：
目录的 key 列表必须正好是 `MODEL_KEYS + ["saw"]`；四个解析模型 `analytic is True`、
SAW 是 `False`；SAW 那三项参数 `used` 全 `False`；`formula` 里那个 ν **必须由
`SAW_NU` 格式化出来**（防手抄一个数字进文案）。这条断言的正是本次要变的契约 ——
所以它不是「测试挡路就改测试」，改的时候是把新契约写进去，同时钉住
「SAW 没混进 `MODEL_KEYS`」这件事。

力–伸长与反解这一侧验的是「反函数真的是反函数」和「换算没有第二套」：

- **Langevin 反函数**：`L(inverse_langevin(λ)) ≈ λ` 往返对拍，λ 越界要抛错
- **高斯线只到 x = 3**：`λ = x/3` 在那里恰好等于 1，再往外没有物理意义
- **单位换算是精确线性逆**：`x_from_force_pn(force_pn(x))` 逐位回到 x
- **反解与内核互为逆**：`solve_n` 出的 n 代回 `compute` 得到原来的 h；
  四种 `kind` 各测一遍，且返回里**必须说清用的是哪一种 h**
- **`force_extension` 不返回整条曲线**（体积护栏），只回查询点 + 一张锚点表；
  参数名是 `lam` 不是 `lambda`（后者在 Python 里不能当关键字参数，会 TypeError）
- **只有 n 会改变绝对伸长**，λ–x 曲线本身与 n、l 无关

能量图景这一侧（`TestChainModels` 里的 8 条）钉的是「图上的数就是内核里的数」，

## 已知限制

- **n < 10 时高斯近似不可靠**。页面会黄条提示：真实 FJC 在小 n 时偏离高斯，
  且在 h→nl 处有硬截断。此时 ⟨h²⟩ = nl² 仍然精确，但分布曲线仅供参考。
- 曲线右端取在 min(nl, h\*+5σ)。小 n 时会被全伸展长度截断，页面同样会提示。
- 3D 视图里 **n > 10000 会提示**「画出来非常密集，构象细节基本看不出来」。
  **不给链模拟加高斯近似警告** —— 单链构象是精确采样，跟高斯近似无关，加了是错的。
- **扫描里 n 挨得太近时斜率本身估不准**。只填 300 和 400，斜率的标准误就有 9%，
  拟合值 0.91 完全在正常涨落里。汇总行会把这条标准误列出来，别把 0.91 当成公式有问题；
  想让斜率准，把 n 铺开到两三个数量级。
- 图上**没有误差棒**，只有 ±2σ 涨落带 —— 那说的是有限样本的散布，不是测量误差。
- **力–伸长的读数取自 400 点采样里 λ 最接近的那个点**（不是插值）：
  `x_max = 10` 时 λ 的分辨率约 0.002，页面上写明了「按曲线上 λ 最接近的采样点读数」。
  前端一个公式都不写 —— 插值就得在 JS 里重算 Langevin，那是第二套物理。
- **Kuhn 预置表不代替物性表**。只有 DNA 和聚乙烯标了实测/推导来源，
  其余是文献标称值；同一种聚合物的 b 能差一倍，要严谨请自己查并直接填 `l`。
- **自回避行走只在 n ≤ 30 上可算**，这不是物理限制而是算力限制：严格拒绝采样的存活率
  每步乘约 0.78，代价随 n 指数增长，n=40 要几分钟。所以这一卡看到的是**渐近区之前的窗口** ——
  实测斜率（默认参数下 1.19~1.23）**必然高于** 2ν = 1.175194，n 越小偏得越多。
  汇总行会给出「与 2ν 相差几个标准误」，别把它当异常。
- **拟合线和 2ν 参考线在图上是分不出来的**（斜率只差 1.6%）。这是物理事实不是画错，
  卡片、汇总行和导出的 JSON 里都写明了 —— 判据是那个 σ 数，不是眼睛。
- 想看更接近 2ν 的斜率就得把窗口挪到大 n（n=16~30 实测 1.1488），但那个窗口只剩 4 个点，
  标准误 0.044，**分辨不出 1.15 和 1.176**。要更窄的误差就得把 n 铺到 30 以上，而那跑不完。
- **3D 的两团并排借用 3D 卡自己的 n 栏**：超过 30 会被夹到 30 并在卡片上写明夹过。
  这个模式下坐标 CSV 置灰（它导的是上一条链的顶点，而画布上是两团格点链），PNG 照常。
- **选中自回避行走时，顶部 n 列表写错不再有顶部报错**。`refresh()` 在这个模型下提前返回
  （这是有意的：不早退就会拿 `model: "saw"` 去打 `/api/compute`，服务端返 400，
  告警条上会挂一条假报错）。代价是「n 必须是正整数」这条校验也一并跳过了 ——
  输入框的 `min` / `step` 还在，3D 卡在「跟随上面的参数」勾着时也会自己报，
  但没勾就没有任何提示。切回任一解析模型，校验立刻恢复。
- **3D 里那两团各 20 条，仍然不是系综平均**：20 条只能把 ⟨R²⟩ 的随机误差压到约 ±15%，
  够看清溶胀（×1.4~2.2）但不够读指数。要读数用下面那张卡片（每个 n 1000 条）。
- 窄屏（手机）上四张图都是等比缩到屏宽，链长扫描与自回避行走那两张的 viewBox 最宽（1240），

  这是给电脑用的工具，手机上建议横屏。
- **能量图景的 ΔE 在 `⟨cosφ⟩ = −0.5` 那端是 −∞，图上画不出来**：曲线截断在 −3 kT、
  当前点画在左边界并标注「ΔE = −∞」。读数行与接口返回的才是真值（那里写「−∞（全 gauche）」，
  JSON 里是 `null` + `all_gauche`）。截断点 −3 处 Cn 与它的下界 Cn_FRC/3 只差 0.3%。
  这一端的两个势垒数也是建在截断值上的（`B_gg` = 12 kT），读数行里注明。
- **能量图景那条 U(φ) 是画法：井底与井深由模型定，势垒高度是约定。** 模型只给一个数
  ΔE，势垒多高另外约定（`TORSION_BARRIER_RATIO = 4`，基准取在两个等价 gauche 井之间）；
  换约定曲线变高变矮，三个井底一动不动。而且这条曲线**不是 120° 周期的** ——
  trans↔gauche 那条势垒恒低于 gauche↔gauche 那条（差由 α 唯一决定），整条是 360° 周期；
  只有 gauche↔gauche 那条有闭式 `4|ΔE|`，另一条从画出来的曲线上量。
- **连续 U(φ) 的玻尔兹曼权重 ≠ 三态权重，所以图上不画连续分布。** 采样器抽的是
  `{0, ±120°}` 三个**离散**值（三态模型），右栏照旧三根柱 —— 别的工具画连续 U(φ)
  得出的光滑三峰在这里会是错的。而左边那条曲线是**势**（模型的输入），它解释
  「三个态为什么长这样」，不参与采样。两栏画的本来就是两件事。
  图上画的是**模型定义**，也不是从某次采样统计出来的直方图 —— 采样器里第 1 个二面角
  没有参考平面，取的是均匀分布，那条不会出现在图上。
- **`κ ≈ p/l + 1/2` 那条渐近线只画 κ ≥ 1 那一段**。再往左它给不出正数（`l/p = 1/κ + 1/(2κ²)`
  的展开在那里失效），画在对数纵轴上会变成 NaN，所以后端就不发那一段。
- **两栏断点刚过的那一小段（约 2000～2075px），能量图景里两张 900 的图会各撑出格子
  十几个像素**：图的高度撑满卡片、宽度是从高度按 viewBox 比例**反推**出来的，而这一档
  两栏的格子只有 831px、反推出来是 849px。多出来的部分落进两栏之间那 20px 的间距里
  （两栏都还在卡片内容盒之内），所以不会被裁掉、也不出横向滚动条，只是两栏的右边缘
  看着不齐；再宽一点格子超过 849px，这个现象自己消失。这是「宽度由高度反推」这条
  既有设计的固有代价（补 `display: block` 之前更宽，是 34px），不是竖向收紧引入的。
